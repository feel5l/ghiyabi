DATABASE SCHEMA (Supabase SQL)
════════════════════════════════════════════
Create these tables using Supabase SQL editor.
Include the SQL in a file: supabase/schema.sql

-- 1. classes
CREATE TABLE classes (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name        TEXT NOT NULL,          -- e.g. "3-A"
  grade_level TEXT NOT NULL,          -- e.g. "Grade 3"
  teacher_email TEXT
);

-- 2. students
CREATE TABLE students (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  full_name     TEXT NOT NULL,
  class_id      UUID REFERENCES classes(id),
  parent_email  TEXT,
  parent_phone  TEXT,
  is_active     BOOLEAN DEFAULT true
);

-- 3. sessions
CREATE TABLE sessions (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  date          DATE NOT NULL DEFAULT CURRENT_DATE,
  period        TEXT NOT NULL,         -- "P1".."P6"
  subject       TEXT NOT NULL,
  class_id      UUID REFERENCES classes(id),
  teacher_email TEXT NOT NULL
);

-- 4. attendance_log
CREATE TABLE attendance_log (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  student_id  UUID REFERENCES students(id),
  session_id  UUID REFERENCES sessions(id),
  status      TEXT DEFAULT 'Present'
              CHECK (status IN ('Present','Absent','Late','Excused')),
  marked_at   TIMESTAMPTZ DEFAULT now(),
  note        TEXT,
  UNIQUE(student_id, session_id)       -- prevent duplicates
);

-- 5. admins
CREATE TABLE admins (
  email TEXT PRIMARY KEY
);

-- ROW LEVEL SECURITY (RLS)
-- Enable RLS on all tables.
-- Teachers: can only see their own classes, sessions, and
--   attendance_log rows linked to their sessions.
-- Admins: full access to all tables.
-- Use auth.email() from Supabase Auth for comparisons.
-- Write the full RLS policies in the schema.sql file.

Also create a seed.sql file at supabase/seed.sql
that inserts all 12 classes and at least 5 sample students
per class for testing.

════════════════════════════════════════════
CORE LOGIC (critical — implement exactly)
════════════════════════════════════════════
When a teacher opens a Session to take attendance:
  1. Check if attendance_log rows exist for that session.
  2. If NOT: auto-create one row per active student in that
     class with status = 'Present' (using a Supabase
     Edge Function or a client-side batch insert on mount).
  3. Teacher then only taps to change students who are absent/late.
  4. Each tap calls an UPDATE (not INSERT) on attendance_log.
  5. This pattern prevents duplicate rows (UNIQUE constraint).

EMAIL NOTIFICATIONS (Supabase Edge Function)
════════════════════════════════════════════
Create a Supabase Edge Function at:
  supabase/functions/notify-absent/index.ts

This function should:
  1. Be triggered by a Supabase Database Webhook on
     attendance_log table for INSERT and UPDATE events.
  2. Check if new status = 'Absent'.
  3. Check if old status was NOT 'Absent' (avoid duplicates).
  4. If both conditions true:
     - Fetch student full_name and parent_email from students table.
     - Fetch date, period, subject, class name from sessions/classes.
     - Send email via Resend API:
         To: parent_email
         From: noreply@ghiyabi.school
         Subject: إشعار غياب — [student name]
         Body (Arabic HTML email):
           "عزيزي ولي الأمر،
           نُحيطكم علماً بأن الطالب/ة [full_name]
           غائب/ة بتاريخ [date] في حصة [period]
           مادة: [subject] — فصل: [class name].
           يُرجى التواصل مع إدارة المدرسة.
           مدرسة زيد بن ثابت الابتدائية"
  5. If parent_email is empty, skip silently.
  Store RESEND_API_KEY in Supabase Edge Function secrets.
